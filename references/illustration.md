# 温暖手绘插图

插图像一页认真画下来的笔记。先决定它帮助读者理解哪一处，再选择形状、角色和颜色。一幅图表达一个核心意思，文字与画面共同把事情讲清楚。

## 图和文章各做什么

正文解释原因、含义、适用条件和作者判断。图展示位置、连线、前后变化、对照及层级。读者能从图中看清关系，从文字中理解它为什么重要。

适合画的地方：两种做法的差别、过程中的变化、难懂机制、角色关系、边界或容易混淆的概念。抽象品质各配一个图标，或把正文整段装进方框，通常没有增加理解。

从已有图表写文章时，先确认图中真实顺序、层级和含义，再组织文字。保留影响结论的机制、差异与边界；完整分类可以由画面展示，正文不必逐项复述。各段围绕它需要解决的问题展开，不能只报“看左边、再看右边”。

### 把细项概括成读者听得懂的一句话

画面已经展示一组细项时，正文先说它们共同回答什么问题。找一个读者熟悉、范围准确的上位说法，再展开会影响理解的差别。

| 图里已有的细项 | 正文可以怎样承接 | 什么时候仍要展开 |
| --- | --- | --- |
| 字号、行距、页边距 | “先把排版调到读着舒服。” | 正文若就在教行距怎么选，仍需讲清具体调整依据 |
| 顺序、分支、并行、循环 | “这些规则决定步骤怎么执行。” | 要解释等待关系时，分清顺着做与同时做，不能只剩“执行更灵活” |

操作顺序是：确认细项的共同作用 → 用一句话概括 → 把关键差异接回来。例如先说“这些规则决定步骤怎么执行”，再用图中的两条路线说明哪些必须等前一步、哪些可以同时开始。正文因此少念标签，却仍把关系讲清楚。

概括不能改变分类层级，也不能把不同作用塞进“全面、系统、能力”等空词。离开图片也要能读懂段意；关键条件不能只藏在图中小字里。

## 选最合适的构图

| 要说明什么 | 构图 | 必须画清 |
| --- | --- | --- |
| 两种写法或做法的差别 | 并排对照或上下对照 | 共同条件、变化处和各自结果，视觉分量相近 |
| 材料经过几步发生变化 | 线性流程 | 每一步处理什么、输出什么；确有返回才画回路 |
| 一个共享对象与多个角色 | 中心与分支 | 谁提供、谁读取、谁决定，连线有明确含义 |
| 不同范围或职责 | 分层与容器 | 边界、包含、依赖或权限，不能混成一组并列项 |
| 若干同级对象 | 小幅并列卡片 | 每项一个可比较的特征；不是步骤就不用顺序箭头 |
| 随时间或状态发展 | 时间线或状态序列 | 各阶段具体变了什么，不能只有编号 |
| 一份文稿、表单或工具本身 | 局部放大与批注 | 真正值得注意的字段、条件或修改位置 |
| 一个容易想象的关系 | 简单场景或物件类比 | 动作与概念如何对应，少用无关布景 |

先用最少元素讲清楚，再增加必要细节。流程通常三到五个节点就能看清，复杂内容可拆图，数量不作配额。箭头只表达已知关系：先后不冒充因果，示意不伪装成测量结果。

## 统一画风

画布以暖米白 `#FBF8EF` 为底，纸纹若有若无。主体通常占画面的 55%–75%，四边留出安静的空白。

用炭黑 `#242824` 勾线，线条略有手画的起伏，粗细清楚。色块平涂，边缘允许少量不齐，形状保持好认。用虚线、弧形箭头、下划线或少量短线强调阅读顺序。

通常选三种低饱和颜色，结构需要时再增加，最多五种。同组图片中的颜色含义保持一致。

| 色彩 | 色值 | 可承担的含义 |
| --- | --- | --- |
| 芥末黄 | `#E5B43B` | 需要注意的差别、判断、重点 |
| 浅珊瑚 | `#E98C72` | 人的动作、问题、冲突 |
| 灰青绿 | `#78B5AC` | 完成、保留、共享状态 |
| 粉蓝 | `#8CB4D8` | 工具、系统与一般过程 |
| 鼠尾草绿 | `#B7BE78` | 边界、持续状态或次要区分 |

人物用圆头、点眼、简单衣服，靠姿势表达观察、比较、修改、传递等动作。机器人可用小圆角矩形头、短天线、深色面屏和两只浅色眼睛。角色必须参与解释，物件已经能讲清时可以不画角色。

避免摄影感、立体渲染、渐变、光泽、厚重阴影、霓虹色和大片深色。线条不要整齐到像办公软件自动排版，也不要为了手绘而歪得难以辨认。

## 文字与画幅

图中的文字使用清楚的手写印刷体，亲切但不幼稚。标签通常两到八字，优先名词和短动词，尽量控制在八个以内。句子对照或用户指定的封面标题可以更长，为文字安排空间，不把字缩到读不清。

准确例句适合做文字特写，关系和机制优先交给画面。主标题可配简短下划线或色块，底部若有结论，与主体留出距离。

比例先服从用户和发布场景。没有指定时，横向封面可用 16:9，正文图可用 3:2；竖图重新安排阅读顺序。不同画幅各自排版，不靠拉伸或裁掉关键文字凑比例。

## 整篇配图的工作流程

先读文章，给每个候选位置写一句“读者看完此图会明白什么”。没有独立理解作用的候选删去。

生成前保存 `shot-list.md`，每行包括：

`正文位置 | 核心意思 | 构图 | 角色动作 | 准确文字 | 比例`

在 `prompts/` 保存每张图的实际提示词，写清以下内容：

```text
使用位置与用途：这幅图帮助理解什么
核心意思：一句话
画面安排：阅读顺序、主次、物件的位置
动作与连线：谁在做什么，箭头表示什么
可见文字：逐字列出标题、标签和例句；无文字则说明
画幅：比例与必要的安全边距
画风：暖米白纸、炭黑手绘线、语义配色、角色与留白
需要保持：事实、方向、概念边界和已确认的元素
避免：无关装饰、错误因果、文字过密和不符合画风的渲染
```

在 Codex 中优先使用内置图像生成工具；用户指定了工具则按其要求。其他环境使用可用的图像生成工具，无可用工具时如实说明缺少成图。逐张生成，首图检查合格后作为后续图的风格参考；保持线条、颜色、字体与角色一致，构图随内容改变。提示词和占位图不等于成图。

每张图核对：核心意思是否一眼可辨，文字是否逐字准确，角色和连线是否有作用，事实与正文是否一致。文字错误或关系错误要针对问题重新生成；反复失败时先简化标签或构图。

保存实际图片到文章目录，嵌入正文并写合适的替代文字。分镜补记最终文件、尺寸、对应提示词、参考图和实际使用的生图工具或后端；模型名可得时一并记录，不可得就标明未提供，不猜测。记录实际生成情况，便于后续修改。

## 使用用户提供的参考图

先查看图片，分清用户是在要求参考它新画一张，还是修改这张图。

- **参考新画**：提取线条、配色、留白、字体感觉和信息密度，再按新内容设计构图。默认不照搬品牌标记、命名角色或整套构图；用户明确要求保留某个元素时，按该要求处理。不能仅把参考图里的文字换掉就当成新的图解。
- **修改原图**：按下节保留已确认内容，只调整用户指定部分。不能把“参考新画”的重构方式套到局部修改上，顺手更换人物、关系或视觉重点。

## 修改已有图片

先查看原图，确认用户指定的修改范围。保留已确认的画风、角色和内容关系，改变需要调整的部分；换画幅时重新排布元素。

重生成时明确列出需要保持与需要改变的内容，保留版本。文字和关系仍逐项复核，不能只因为画风相似就视为完成。
